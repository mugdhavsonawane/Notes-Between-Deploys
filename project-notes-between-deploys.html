I wanted a website, but instead of writing every line of HTML and CSS from scratch, I decided to see if AI could do the heavy lifting. Welcome to my Prompt Engineering Project, where I formulated requirements, let ChatGPT and Gemini generate the files, and figured out how to deploy the results to the world.

What I built

I built a minimalist website by acting as the architect and letting AI be the developer. I formulated specific requirements and prompted ChatGPT and Gemini to generate all the necessary code and structural files for a web project.

Getting the initial raw HTML and CSS was just the first step. From there, I went through numerous iterations—reviewing the generated code line-by-line, tweaking my prompts, and working back-and-forth with the AI to perfect the layout, styling, and structure. Once the code finally met my standards, my job shifted to implementation: organizing the source files, fixing directory paths, and configuring the environment so the site could actually live on the internet instead of just sitting in a chat window.

Highlights

  • Key learning #1: AI needs specific requirements. You can't just say "build me a website" and expect a finished product. I had to formulate specific prompts and iteratively guide the AI to generate the exact HTML, CSS, and layout structures I needed.

  • Key learning #2: Iteration and review are critical. The AI rarely gets it perfect on the first try. I had to read through the generated code, spot layout or logic issues, and iteratively refine my prompts to get the exact result I wanted before manually linking everything together into a cohesive unit.

  • Key learning #3: Deployment takes research. I had the static files, but I had to research, configure, and successfully deploy them to GitHub Pages myself to make the site publicly accessible.

Architecture Approach

The architecture relies entirely on AI-generated static files. It’s a purely static site: no heavy backend, no database to maintain, just plain HTML and CSS files served straight to the browser via GitHub Pages.

The main tradeoff is that maintaining or scaling the site means going back to the AI, or digging through the code and figuring it out for myself. If I want to add a complex feature later, I have to figure out how to prompt the AI to update the existing codebase without breaking the layout. But for getting a fast, reliable site off the ground, this workflow was incredibly efficient. 

YAML# .github/workflows/deploy.yml
name: Deploy static content to Pages

on:
  push:
    branches: ["prod"]

jobs:
  deploy:
    environment:
      name: prod
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
      - name: Deploy to GitHub Pages
        uses: actions/deploy-pages@v4

The Deployment Strategy

You might think a website built by AI wouldn't need a deployment strategy. You would be wrong. Taking raw text from a chatbot and turning it into a live website requires a solid hosting and version control approach. To keep the project disciplined, I applied the same enterprise branching strategies I use at my day job, eventually deploying via GitHub Pages.

  • The dev branch: This is my drafting room. It's where I gathered the iterative files ChatGPT and Gemini generated, tested them in my local browser, and worked through the back-and-forth prompt refinements until the code was perfect.

  • The main branch: The pristine vault. Once the code in dev met all my requirements and was properly organized, it was merged here as the absolute source of truth for the codebase.

  • The prod branch: The live environment. Code merged from main to prod serves as the final step, triggering the GitHub Actions workflow above to serve these static HTML files directly to the public internet.
You might notice a glaring omission: Where is the backend configuration?

There isn't one. Since the AI generated purely static files, I didn't need to spin up a complex server, database, or staging environment. If the HTML files looked good when I tested them locally on my dev branch, they were ready to be pushed up the chain to live on GitHub Pages.

Results

The result is a fully functional, publicly accessible website. Performance is excellent because serving plain HTML is as fast as the internet gets. But the real impact was the learning experience: I successfully bridged the gap between raw AI generation and real-world deployment, learning how to leverage tools like ChatGPT and Gemini for actual web development while applying professional version control standards.
