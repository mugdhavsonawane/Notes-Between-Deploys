Notes Between Deploys: A Prompt Engineering Project

Published 2026-02-05

I wanted a website, but instead of writing every line of HTML and CSS from scratch, I decided to see if AI could do the heavy lifting. Welcome to my Prompt Engineering Project, where I formulated requirements, let ChatGPT and Gemini generate the files, and figured out how to deploy the results to the world.

What I built

I built a minimalist website by acting as the architect and letting AI be the developer. I formulated specific requirements and prompted ChatGPT and Gemini to generate all the necessary code and structural files for a web project.

Once the AI handed over the raw HTML and CSS, my job shifted to implementation. I had to organize the provided source files, ensure proper directory structures, and configure everything so the site could actually live on the internet instead of just sitting in a chat window.

Highlights

  • Key learning #1: AI needs specific requirements. You can't just say "build me a website" and expect a finished product. I had to formulate specific prompts and iteratively guide the AI to generate the exact HTML, CSS, and layout structures I needed.

  • Key learning #2: Implementation is still a human job. The AI gave me the files, but getting a bunch of raw code means nothing if the files aren't linked correctly. I had to organize the output and fix directory paths to ensure the site worked as a cohesive unit.

  • Key learning #3: Deployment takes research. I had the static files, but I had to research, configure, and successfully deploy them to GitHub Pages myself to make the site publicly accessible.

Architecture Approach

The architecture relies entirely on AI-generated static files. It’s a purely static site: no heavy backend, no database to maintain, just plain HTML and CSS files served straight to the browser via GitHub Pages.

The main tradeoff is that maintaining or scaling the site means going back to the AI, or digging through the code and figuring it out for myself. If I want to add a complex feature later, I have to figure out how to prompt the AI to update the existing codebase without breaking the layout. But for getting a fast, reliable site off the ground, this workflow was incredibly efficient.

The Deployment Strategy

You might think a website built by AI wouldn't need a deployment strategy. You would be wrong. Taking raw text from a chatbot and turning it into a live website requires a solid hosting approach. I chose GitHub Pages for this.

  • The Local Environment: This is where I gathered the files ChatGPT and Gemini spit out, tested them in my browser, and organized the directories.

  • The Git Repository: I pushed the finalized, AI-generated source files into a GitHub repository. This became the absolute source of truth for the codebase.

  • GitHub Pages Configuration: I researched how to enable GitHub Pages on the repository, pointing it to serve the static HTML files directly to the public internet.
You might notice a glaring omission: Where is the backend configuration?

There isn't one. Since the AI generated purely static files, I didn't need to spin up a complex server, database, or staging environment. If the HTML files looked good when I opened them on my laptop, they were ready to be pushed live to GitHub Pages.

Results

The result is a fully functional, publicly accessible website. Performance is excellent because serving plain HTML is as fast as the internet gets. But the real impact was the learning experience: I successfully bridged the gap between raw AI generation and real-world deployment, learning how to leverage tools like ChatGPT and Gemini for actual web development.
